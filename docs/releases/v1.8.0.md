# Petrophyter v1.8.0 (Build 20261013)

Petrophyter v1.8.0 adds rock typing from core. Core porosity and permeability become RQI and FZI, rock types are fitted once on the core and applied to every well through the logs, and net pay, HCPV and permeability are reported per rock type. Rock typing is optional: **until you turn it on, results, exports and saved sessions are the same as in v1.7.3.**

## New

- **Rock Typing tab** (after Diagnostics).
  - **Core QC.** Every core row with porosity and permeability gets one status; rows left out are counted by reason and well (missing value, permeability not positive, porosity outside 0.01–0.50, no depth), together with the values the core loader had already blanked. Samples more than three standard deviations from their well's mean log10 FZI are listed, not removed.
  - **Fit.** Rock types are fitted on log10 FZI with a seeded k-means, so the same data give the same rock types every time; rock type 1 is the lowest FZI. The tab suggests a count from the silhouette score; you choose the count. **Fit scope** is **Project pooled** (default: the same rock type is the same rock in every well), **Per well** or **Per zone**, with the pooled set used where a well or zone has too few samples. **Winland R35** is offered as a second method with the fixed port-size classes (nano to mega).
  - **Review.** FZI histogram and normal-probability plot, Phi-K with constant-FZI curves, RQI-phiz, R35 with the 0.1, 0.5, 2 and 10 µm lines, and the Lorenz curve with the stratigraphic modified Lorenz plot and its flow-unit segments.
  - **Apply to project** is the only step that writes the definitions. The definitions table can be edited (boundaries and FZI per type); edits never refit. A banner says when the core or the fit settings changed since the fit.
  - Overburden and Klinkenberg corrections are not applied; the report says so unless you enter porosity and permeability factors.
- **Rock types in the run.** With **Enable rock typing in the analysis** checked, every well gets `RQI`, `FZI`, `ROCK_TYPE` (0 = unassigned), `ROCK_TYPE_SOURCE` (`core`, `log`, or why the sample was left out) and `RT_MARGIN`. A log sample within the core matching distance of a core sample takes that sample's rock type. Uncored intervals and wells get a rock type from the log FZI (PHIE and the Timur or Wyllie-Rose permeability), and the run warns that these are log-derived. Near-boundary samples, samples outside the fitted range and the core-versus-log agreement are counted.
- **Permeability per rock type.** `PERM_RT` uses each rock type's FZI with the log PHIE. **Primary permeability** on the Parameters Permeability page (Timur, Wyllie-Rose or Rock type; project or well) chooses the permeability that feeds `FLOW_UNIT` and the quality flags. If Rock type cannot be used, the well uses Timur and the run warns.
- **Pay and HCPV per rock type.** The Summary shows gross sand, net reservoir, net pay, averages, HCPV, geometric-mean permeability and the share of core-labelled samples per rock type, plus the unassigned samples; the rock types add up to the well totals. With several wells, a field total per rock type appears only when every well uses the project-wide definitions.
- **Exports.** The Excel workbook adds a **Rock Types** sheet; CSV and Excel results carry the new columns; LAS writes `ROCK_TYPE`, `FZI`, `RQI`, `RT_MARGIN` and `PERM_RT`. **Export definitions** saves the definitions table to CSV.
- **Rock Type log track.** A seventh track with one colour per rock type, faded where the rock type comes from the log or lies near a boundary.
- **Next step shown.** Turning rock typing on computes nothing by itself. The line under the checkbox says to run the analysis (with a **Run All Wells** button) and, after the run, where the rock types are: Summary, Log Display and the exports. Until then the Summary's Rock types group shows the same hint.

## Sessions

- A session that uses rock typing is saved as format **2.2** with the definitions and settings. A session that does not use it is still saved as 2.1.
- **A 2.2 session opens in v1.7.x without the rock types**, and saving it again there drops them.
- A session saved by a newer Petrophyter with a higher major format is refused with "This session was saved by a newer Petrophyter (format X.Y). Update Petrophyter to open it." instead of being opened as an older format.

## Quality

- Results of every existing reference case are unchanged; one reference case with rock typing on is added.
- The Rock Typing tab redraws only what changed and only the plot on screen, so switching wells or running with the tab open stays fast.
- The test suite has 1507 tests.

## Known issues

- Rock types in uncored intervals are a surrogate: they inherit the shape of the Timur or Wyllie-Rose permeability. Calibrating Wyllie-Rose to core first reduces the bias; the core-versus-log agreement shows how far to trust them in a well.
- Winland R35 was derived on sandstones.
- The window title shows the active well, not the session file name.
- The Interactive log engine is verified on axes and items in automated tests; its drawing is checked by hand on a real display.

## Installation

1. Download `Petrophyter_Setup_1.8.0_Build20261013.exe` from **Assets**.
2. Optionally verify it using `SHA256SUMS.txt`:

   ```powershell
   Get-FileHash .\Petrophyter_Setup_1.8.0_Build20261013.exe -Algorithm SHA256
   ```

3. Run the installer and launch **Petrophyter** from the Start Menu. Installing over v1.7.3 upgrades it in place.

> Windows SmartScreen may appear because the installer is unsigned. Select **More info → Run anyway** only after confirming the SHA-256 hash.
