# Petrophyter v1.12.0 (Build 20261105)

Petrophyter v1.12.0 adds Rt corrections to the LRLC Workbench. Three common causes of low-resistivity pay can now be corrected: thin sand-shale laminations, conductive pyrite and clay conductivity. The Workbench names the probable cause per zone, prepares the remedy, and compares pay before and after the corrections. Everything is optional: **until you switch a correction on, results, exports and saved sessions are the same as in v1.11.0.**

## New

- **Thomas-Stieber laminar and dispersed shale.** From Vsh and total porosity, each sample gets a laminar shale volume `VLAM`, a dispersed shale volume `VDISP`, a sand-lamina porosity `PHI_SAND` and a class `TS_CLASS` (laminar, dispersed, mixed, structural, clay-supported). The clean-sand and shale porosity end-points are proposed per zone from the clean and shale samples and written only when you apply them. Samples outside the triangle are clamped to its edge and counted.
- **Laminated-sand Rt (Hagiwara).** The `laminated` step of the Rt chain removes the conductance of the shale laminae (parallel model with Rsh) and writes `RT_SAND`. The laminar volume comes from Thomas-Stieber or a constant. Samples where the shale laminae carry almost all the current are warned about or left without a corrected value, with thresholds you can edit.
- **Sw on the sand laminae.** After the laminated-sand step the Sw models can read the sand-lamina porosity and the dispersed shale of the sand (sand basis, the default when the step is on) or the bulk values. With the bulk basis the run warns that Indonesian and Simandoux count laminar shale twice.
- **Pyrite.** `VPYR` from a manual value or from RHOB and PEF with editable mineral end-points (pyrite 4.99 g/cc and 16.97 b/e by default). The `pyrite` step removes the conductance of the connected pyrite fraction and writes `RT_PYR`. The run warns that pyrite biases the density porosity.
- **Qv from shale CEC.** `QV_EST` from Vsh, total porosity and a shale CEC, used per sample by Waxman-Smits in the zones that choose the estimate. With core CEC loaded, the Workbench proposes a shale CEC calibrated on the core samples.
- **Core CEC.** Core data files may carry an optional CEC column (meq/100 g), recognised by name or assigned in the import dialog.
- **Shoulder-bed guard.** In zones that Thomas-Stieber classes as laminated, Rt steps that assume thick beds are held back, and a resistivity marked as shoulder-bed corrected is flagged. **Specialized → Shoulder-bed Guard (laminated zones)** switches it on or off for the project (on by default).
- **Specialized → Rt Corrections** with **Laminated Sand Rt (Hagiwara)…** and **Pyrite Correction…**, which open the matching Remediation section.
- **Workbench panels.**
  - **Diagnosis**: a table of zones with the probable cause (thin beds, microporosity, saline water, conductive minerals, clay conductivity), its evidence and the remedy, plus a Thomas-Stieber page with the end-point proposals, class counts and a crossplot of the zone's samples coloured by class. Zone links in the Data Browser now open this panel.
  - **Remediation**: the Rt each zone's Sw reads (`RT_PYR ← RT_SAND ← RT`), the guard status, and sections for the laminated sand, pyrite (with a PEF-RHOB plot showing the pyrite mixing line), clay Qv and the Sw basis. **Apply** writes the values you changed to the zone, the well default or the project default; nothing is recomputed until you run.
  - **Validation**: net pay, average Sw and HCPV before and after the corrections per zone, an Sw depth plot, and the saturation-height comparison when one exists.
- **Baseline.** When an Rt correction is active the run also computes `SW_BASE` and `NET_PAY_BASE_FLAG` from the measured Rt, so the effect of the corrections can be read directly. Summary shows the baseline net pay, Sw and HCPV per zone.
- **Log display.** `VLAM` dotted on the GR/Vsh track, `SW_BASE` dashed on the Sw track, `RT_SAND` and `RT_PYR` on the resistivity track, in both log engines. `VPYR` and `QV_EST` appear in the crosshair readout of the interactive log.
- **Monte Carlo.** When Rsh is varied, the laminated-sand Rt is recomputed with each draw. The laminar volume, pyrite volume and correction and the estimated Qv stay at their base values and are listed as not varied.
- **Exports.** The new columns in CSV, Excel and LAS, with LAS curve descriptions. The provenance block adds an "LRLC inputs" line (end-points, Qv, pyrite, Sw basis, guard) when any of these features is used. The Excel zone sheet adds the before/after pay and the probable cause when present.
- **New application icon.**

## Sessions

- A session is saved as format **2.6** only when one of the new features is configured (Thomas-Stieber, pyrite, Qv, guard or diagnosis settings, a laminated or pyrite step, or a resistivity marked as shoulder-bed corrected). Any other session is saved as 2.5 or older as before.
- **A 2.6 session opens in v1.11.0** with a notice that settings it does not know were not loaded. There the laminated, pyrite and Qv corrections are not applied, so Sw and pay can differ from v1.12.0.

## Calculation changes

- None to existing results: every reference case is unchanged relative to v1.11.0, and with the new features off Sw, pay and HCPV are identical. Two new reference cases cover a laminated sand (the corrected Rt recovers the forward-model Sw) and a pyritic sand (the pyrite volume and corrected Rt are recovered).

## Known issues

- The Thomas-Stieber model assumes constant sand and shale porosity per zone and a total porosity free of shale and gas effects. Its classes are a screening aid, not a lithofacies log.
- The laminated-sand correction uses one Rsh per zone (the shale laminae are assumed to look like the thick shale) and does not model shale anisotropy.
- The default shale photoelectric factor is the average-shale value of 3.42 b/e. Shales range from about 3 to 3.5 b/e and read higher with iron-bearing minerals, so set it from a shale in your well.
- The diagnosis thresholds are design defaults; calibrate them per field.
- The reference "Tolioe et al. (2016)" is still marked "to be confirmed".

## Installation

1. Download `Petrophyter_Setup_1.12.0_Build20261105.exe` from **Assets**.
2. Optionally verify it using `SHA256SUMS.txt`:

   ```powershell
   Get-FileHash .\Petrophyter_Setup_1.12.0_Build20261105.exe -Algorithm SHA256
   ```

3. Run the installer and launch **Petrophyter** from the Start Menu. Installing over v1.11.0 upgrades it in place.

> Windows SmartScreen may appear because the installer is unsigned. Select **More info → Run anyway** only after confirming the SHA-256 hash.
