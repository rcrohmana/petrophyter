# Petrophyter v1.7.1 (Build 20261011)

Petrophyter v1.7.1 is a trust-and-safety release. Bad input no longer crashes or silently distorts a run: values ≤ 0, null sentinels in core data, unit mismatches, and out-of-range depths are caught at load and counted. Merging never extrapolates past a file. Every run now tells you what it had to work around, and every export records what produced it. Sessions keep each merged well's own recipe and protect unsaved work. Results on data that ran in v1.7.0 are unchanged except in the cases listed under [Calculation changes](#calculation-changes).

## Highlights

### Trust and safety in the interface

- **Run issues.** A run that had warnings shows a warning banner with **Review**, which opens **Diagnostics → Run issues**. Run issues lists every error, warning, and note of the well's last run, with its zone and a **Go to** button for the related setting. The Data Browser shows a count such as **2 warnings**, and the Summary Wells table has an **Issues** column.
- **Used in last run.** The Summary and Diagnostics tabs show the parameters the last run used, not the current settings, with the hint **Current settings differ — Run to update** when they no longer match.
- **Export freshness.** The Export tab says whether results are current. Exporting wells that are out of date, or whose latest run failed, asks you to **Run out-of-date wells**, **Export last successful results**, or **Cancel**.
- **Provenance in every export.** Excel gets a **Provenance** sheet, LAS an `~OTHER` section, and CSV a `<name>.provenance.txt` file. Each records the version, run time, status, parameter hash, and issue counts. The Excel Summary sheet lists every parameter used as a table instead of JSON.
- **Stop analysis.** Stop a run from the Analysis menu, the toolbar, or with `Esc` while it runs. Finished wells keep their results.
- **Unsaved changes.** An asterisk in the window title marks unsaved changes. **Save Session** (`Ctrl+S`) writes to the current file, and **Save Session As…** (`Ctrl+Shift+S`) is new. Closing, loading a session, or starting a new project asks Save, Discard, or Cancel.

### Safer input

- Resistivity, RHOB, and DT samples ≤ 0 are set to empty at load and counted. A resistivity ≤ 0 used to crash the run.
- Core null values (such as −999.25) and non-physical values are excluded and counted. A failed core calibration now says why.
- Declared curve units are checked against the values, depths outside −1 000 to 60 000 ft are refused, and a header TD or BHT without a unit is flagged in the temperature readout.
- A tops column named like `Top TVD` is flagged as TVD, as core data already were.
- Files over 500 MB and merges that would need more than 2 000 000 depth points or about 1 GB are refused before they start.
- Exported text that starts with `=` is never written as a spreadsheet formula. In CSV, text that starts with `= + - @` gets a leading `'`.

### Merging and sessions

- Merging no longer stretches the first and last values of a file past its ends, keeps measured values at measured depths, interpolates resistivity in log10, and accepts TVD and MD curves.
- Each merged well stores its own merge step and gap limit in the session. Restoring a project whose wells were merged at different steps rebuilds each one as it was merged.
- A session load that fails, or skips every well, keeps the open project as it was.
- Sessions record the Petrophyter version that saved them.

### Build and quality

- `requirements-lock.txt` pins the release environment. The build script runs the full test suite before building, checks the built application with `Petrophyter.exe --self-test`, and writes `SHA256SUMS.txt` with the environment manifest. A GitHub Actions workflow runs the tests and the build on every push.
- `docs/calculation-methods.md` now matches the code: the three Vsh methods, the Indonesian closed form, the Simandoux form used, and a new section on automatic Rw and Rsh.
- The test suite has 1078 tests and runs in parallel with `pytest -n 8`.

## Calculation changes

On data that ran in v1.7.0, results are unchanged, except:

- **Merged wells** may change: values past a file's ends are no longer extrapolated, measured samples at a gap edge are kept, and resistivity is interpolated in log10. Sessions saved by v1.7.0 stored the project's last merge step for every merged well. Such wells are merged again under the new rules with that step, and a banner note names the step and the row count. If a merged well's row count looks wrong, import it again with **Merge LAS Files**.
- **Runs that substituted a porosity of 0.15** where no porosity method gave a value: those samples now have no PHIE and drop out of Sw, pay, and HCPV, and the run reports how much of the interval has porosity.
- **Input curves named like result columns** (`PHIE`, `SW`, …) are kept as `<NAME>_IN`. Before, they collided with the results and broke the export.
- **Per-Formation selections that match no formation** of a well are now an error for that well instead of analysing the whole well.
- **Core validation statistics** leave out core samples beside a gap in the log ("N core samples in log gaps").
- **Field total.** The Wells table and the all-wells Excel leave out wells whose latest run failed. This changes the total only when a failed well still had results from an earlier run.
- Resistivity, RHOB, and DT samples ≤ 0, and core null or non-physical values, no longer enter any calculation.

## Known issues

- The calculation corrections reviewed for this release (total porosity on every path, Dual-Water and Waxman-Smits Sw, the auto-Rw method, pay thickness and averages) ship in v1.7.2. Sessions saved by v1.7.1 will show a notice there.
- The window title shows the active well, not the session file name.
- The hint that a deviated well was assumed vertical rarely appears, because the LAS parser does not read inclination or deviation header entries. Map a TVD curve for deviated wells.
- The multi-well import dialog is wide (about 1180 px); on small screens its well table scrolls horizontally.

## Installation

1. Download `Petrophyter_Setup_1.7.1_Build20261011.exe` from **Assets**.
2. Optionally verify it using `SHA256SUMS.txt`:

   ```powershell
   Get-FileHash .\Petrophyter_Setup_1.7.1_Build20261011.exe -Algorithm SHA256
   ```

3. Run the installer and launch **Petrophyter** from the Start Menu. Installing over v1.7.0 upgrades it in place.

> Windows SmartScreen may appear because the installer is unsigned. Select **More info → Run anyway** only after confirming the SHA-256 hash.
