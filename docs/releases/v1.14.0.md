# Petrophyter v1.14.0 (Build 20261115)

Petrophyter v1.14.0 adds Rt deconvolution for thin beds and an elastic flag to the LRLC Workbench, iso-saturation curves from the variable m model on the Pickett plot, and an LRLC report in the exports. Both new features are optional: **results are unchanged unless you add the deconvolution step to a zone's Rt corrections or switch the elastic flag on.**

## New

- **Rt deconvolution (thin beds).** The `decon` step of the Rt chain sharpens the deep resistivity in beds thinner than the tool's vertical response. It is the first step of the chain, so every later step reads `RT_DECON`. Open it from **Specialized → Rt Corrections → Rt Deconvolution…** or from the **Rt deconvolution** page of the Remediation panel.
  - Bed boundaries are picked from one high-resolution **reference curve** (`HIRES`, `RXO`, `RHOB` or `GR`, chosen automatically in that order unless you pick one). The deep curve is then solved for one resistivity per bed in the conductivity domain, with a bounded, regularised least-squares solve.
  - **Tool presets** (array induction 1, 2 and 4 ft, deep laterolog 2 ft, deep dual induction 8 ft, custom) set the **response width** (FWHM, ft). The response is Gaussian; a Doll geometric-factor response is offered as an alternative.
  - **Propose** previews the result for the zone in a background task, with the reference curve, the measured and deconvolved deep curves and the picked boundaries. You can add, remove and restore boundaries; **Use proposal** copies the inputs and the edits into the form, and they are written, like every other change, on **Apply**.
  - Under the result, a line shows the **response-width sensitivity**: the median Rt increase in the raised beds at 0.8, 1 and 1.25 times the response width, with the count of samples over the change limit at a width where some were rejected.
  - The page lists the windows with their misfit, and the counts of beds, amplified samples, samples set to empty and boundaries dropped. A zone that the shoulder-bed guard blocks says so and why, with a link to the laminated-sand page.
  - The settings under **Advanced settings** (smoothing, edge threshold, minimum contrast and bed thickness, window and overlap, solver, smoothing weight, noise, change limit, misfit warning) are a collapsed section that opens by itself when a value differs from its default.
- **Elastic flag on Screening.** A new **Elastic flag** section computes `AI` (acoustic impedance) and `VPVS` from `RHOB`, `DT` and a shear slowness curve (`DTS`, mapped on **Screening → Curves**), compares them with a shale baseline and a robust wet-sample trend against porosity, and writes `ELASTIC_FLAG` where both fall below the trend by more than the thresholds in net reservoir. The section shows the curves it reads, a table per zone and two crossplots. Without a `DTS` curve it says so and the stage is skipped. Its thresholds sit in a collapsed **Advanced settings** section that opens by itself when a value differs from its default.
- **Pickett iso-Sw curves from the variable m model.** For a single zone in Curve mode the iso-Sw lines are computed with the variable m model (the formula or the Shell formula, at the zone's median Vsh) instead of the constant m, and a note says which model drew them and which porosity it read. When several zones are plotted and some use curve mode, the lines keep the constant m and the note says so.
- **LRLC report in the exports.** The Excel export gains an **LRLC** sheet with three tables (zones, the Rt correction chain, and the references that the exported wells cite). A CSV export writes three more files next to the CSV, `<name>.lrlc_zones.csv`, `<name>.lrlc_steps.csv` and `<name>.lrlc_refs.csv`. The zones table includes the deconvolution status and the response-width sensitivity of each zone. The sheet and the files are written only when a well has an LRLC run.
- **One-line method strips on Screening.** The Method & Reference boxes of the screening and the Rt cutoff are now one line, like those on the Remediation pages; the link opens the full write-up in the Methods panel.
- **New columns.** `RT_DECON` (ohm.m), `AI`, `VPVS` and `ELASTIC_FLAG` (unitless) appear in CSV, Excel and LAS, with LAS units and curve descriptions. `RT_DECON` is drawn on the resistivity track of both log displays (dotted), and `ELASTIC_FLAG` is shaded on the flags track beside `LRLC_FLAG`; `AI` and `VPVS` are in the cursor readout.

## Reading the new results

- **The deconvolved Rt depends on the response width.** The presets are generic widths, not specifications of any tool: confirm the width against the charts of the tool that was run. The sensitivity line shows how much the answer moves with it.
- **Beds thinner than the response width are only partly recovered.** The result is a bed-model estimate, not a measurement. It ignores skin effect, dip, anisotropy, borehole and invasion, and it amplifies noise. Array induction curves already carry their own vertical enhancement, so applying the step to them enhances twice.
- **The misfit warning is automatic.** Unless you set a value, a window is reported as fitting badly when its relative misfit exceeds twice the relative noise you set for the deep curve.
- **The Doll response is offered as it is.** Its formula has not been checked against Doll (1949), and the page and the method text mark it *to verify*. Use the Gaussian response unless you have a reason to prefer the Doll one.
- **The elastic thresholds are starting values.** They are design defaults, to be calibrated on wells with known fluids. The flag adds one point to `LRLC_SCORE` (a well where it ran scores 0 to 7) and **never changes `Sw`, pay, HCPV or `LRLC_FLAG`**.

## Sessions and out-of-date wells

- A session is saved as format **2.8** only when the project switches the elastic flag on, a zone uses the `decon` step, or a deconvolution or elastic setting differs from its default. Any other session is saved as 2.7 or older as before.
- **A 2.8 session opens in v1.13.0** with a notice that settings it does not know were not loaded. There the deconvolution step is skipped with a note and the Sw models read the measured Rt, or the output of the other steps, so `Sw` and pay can differ from v1.14.0; the elastic settings are not loaded.
- **Wells with LRLC switched on show as out of date once after the upgrade**, because the new settings are part of the parameter hash. Running them again gives the same numbers. Wells without LRLC are not affected.

## Fixes

- The Pickett plot draws its iso-saturation lines with the variable m model for a single zone in curve mode (see New). This closes the v1.13.0 known issue for that case.
- The reference "Guo et al. (2023)" is now confirmed against its record, and the details of "Coll et al. (1993)" and "Tolioe et al. (2016)" are filled in.

## Calculation changes

- None to existing results. The two new features are off until switched on, and every existing reference case is unchanged relative to v1.13.0. `LRLC_SCORE` changes only in wells where the elastic flag is on and a `DTS` curve is mapped; `LRLC_FLAG` never changes because of it. Two new checks cover the deconvolution of a three-bed synthetic well and the elastic equations on one worked sample, and a new end-to-end test runs every Rt step on a synthetic well with known answers.

## Known issues

- The tool presets of the deconvolution are generic widths, not vendor specifications. The Doll formula is not yet checked against the original paper.
- The deconvolution needs a reference curve that resolves the beds. With a smooth reference, boundaries are missing and the page reports windows with a high misfit.
- The invasion model is a step profile only: no annulus, transition zone or flushing gradient. It is not a substitute for the service company's tool-specific charts.
- There is no fit for the saturation exponent `n`.
- The elastic flag reads sonic and density, which see the flushed zone, so invasion can weaken the contrast. Gassmann fluid substitution is not modelled.
- The reference "Tolioe et al. (2016)" is still marked "to be confirmed".

## Installation

1. Download `Petrophyter_Setup_1.14.0_Build20261115.exe` from **Assets**.
2. Optionally verify it using `SHA256SUMS.txt`:

   ```powershell
   Get-FileHash .\Petrophyter_Setup_1.14.0_Build20261115.exe -Algorithm SHA256
   ```

3. Run the installer and launch **Petrophyter** from the Start Menu. Installing over v1.13.0 upgrades it in place.

> Windows SmartScreen may appear because the installer is unsigned. Select **More info → Run anyway** only after confirming the SHA-256 hash.
